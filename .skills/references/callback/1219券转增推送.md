## 概述

本文档描述如何对接EZR开放平台的推送回调接口。推送回调与普通接口的主要区别在于：

- 推送没有现成的接口地址，需要自定义接口地址
- 推送是对接其他第三方的接口或者自定义业务处理

### 接口说明

#### 接口基础信息

| 项目 | 说明 |
|------|------|
| 接口编号 | 1219 |
| 接口名称 | 券转增推送 |
| 接口地址 | /api/Coupon/CouponChange |
| 协议 | HTTPS |
| 请求方式 | POST |
| 数据格式 | application/x-www-form-urlencoded |
| 字符编码 | UTF-8 |

#### 功能描述

当券的基础信息发生变更后，EZR系统会通过该接口实时推送变更信息给第三方系统。例如：会员赠券、券转赠等场景，会改变券的所属会员。

## 请求结构

### 外层请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| AppId | string | 是 | 品牌编码，由 EZR 分配 |
| Sign | string | 是 | 请求签名 |
| Timestamp | string | 是 | 请求时间戳，格式 `yyyyMMddHHmmss` |
| AppSystem | string | 是 | 系统来源标识 |
| Args | string | 是 | 业务请求参数JSON字符串 |

### 业务请求参数（Args）

Args为JSON字符串，解析后为券变更信息对象，包含以下字段：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| Brand | string | 所属品牌编码 |
| CoupNo | string | 券号码 |
| CoupType | int | 券类型：1=品牌代金券；2=品牌折扣券；3=品牌促销券 |
| VipCode | string | 新的会员卡号（线下卡号） |
| ChangeTime | string | 变更时间（yyyy-MM-dd HH:mm:ss格式） |
| IsAvailable | bool | 是否可用 |
| ChangeRemark | string | 变更描述/备注 |
| MobileNo | string | 手机号码 |
| CoupGrpCode | string | 券库外部编码 |
| coupStatus | long | 券状态：1=可使用；2=已锁定；4=已禁用；8=已核销；11=释放锁定 |
| UnLock | bool | 是否解锁 |
| BeforeVipCode | string | 分享会员卡号（变更前的会员卡号） |
| BegDate | string | 有效开始日期（yyyy-MM-dd HH:mm:ss格式） |
| EndDate | string | 有效结束日期（yyyy-MM-dd HH:mm:ss格式） |
| DyOpenId | string | 抖音OpenId |
| UseSystem | string | 使用系统 |
| ChangeOutSysId | int | 变更来源系统ID |

## 注意事项

1. **Controller命名**：Controller名称应具有明确的业务含义
2. **Action命名**：Action名称应清晰表达业务用途
3. **参数解析**：使用 `FastJsonSerializer.FromJson` 解析Args参数
4. **异常处理**：统一使用 try-catch 捕获异常并返回错误信息
5. **业务处理**：接收到推送后，需要根据BeforeVipCode和VipCode更新券的所属会员
6. **券状态判断**：根据coupStatus字段判断券当前状态，1=可使用，2=已锁定，4=已禁用，8=已核销
